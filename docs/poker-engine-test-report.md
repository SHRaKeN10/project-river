# Poker engine — test report & known limitations

`@river/poker-engine` · **24 test suites · 258 tests · all passing**
(plus the API multiplayer layer: 9 `TableRunner` unit tests + 19 API e2e).

Run it yourself:

```bash
pnpm --filter @river/poker-engine test
pnpm --filter @river/api test           # unit incl. TableRunner
pnpm --filter @river/api test:e2e       # needs docker infra up
```

## Known limitations & edge cases

**Deliberately out of scope (per the product brief)**

- No rake, no real money, no deposits/withdrawals.
- NLHE cash only — no PLO/Big O/Hi-Lo, no tournaments/SNGs, no straddles, bomb pots, run-it-twice, or time banks.

**Simplifications (correct per hand, imperfect for a long-running live table)**

- **Moving button.** The button always advances to the next eligible seat and the small blind is always posted by someone. No dead-button / dead-small-blind rules, and a player joining between the button and the big blind isn't forced to post — they're simply dealt in from the next small blind. This only affects exact positional fairness across sit-downs, never the math of a hand.
- **Odd chips** go to the first contesting seat left of the button (a common online rule). Some card rooms award them by high card by suit instead.
- **No auto-muck.** Every non-folded hand is revealed at showdown; a beaten player's cards are shown. `HAND_MUCKED` exists in the event type but is unused. Cosmetic.

**Disconnect / recovery**

- A disconnected player is auto-folded/checked only when their normal action timer expires — there's no separate shorter "disconnect grace" timer. Their `connected: false` flag is shown to the table.
- `PlayerStatus.Disconnected` is in the enum for the wire contract but the reducer never sets it (disconnect is a runner/roster concern).
- Snapshot recovery restores an in-progress hand but only re-arms the action timer once _someone_ reconnects; if the entire table drops and nobody returns, the hand sits idle until the table is torn down.
- Access tokens are stateless — a kicked/logged-out player's JWT works until it expires (≤10 min). See ADR-0002.

**Test coverage gaps (low risk)**

- The randomized simulation drives only _legal_ actions (chosen via `legalActions`); it doesn't fuzz malformed payloads. The explicit rejection-matrix tests plus `reduce` being total cover that path instead.
- The heads-up "both blinds exceed a short stack" edge is exercised by the random sim but has no dedicated named test.
