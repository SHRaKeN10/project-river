# Poker engine — test report & known limitations

`@river/poker-engine` · **26 test suites · 267 tests · all passing**
(plus the API multiplayer layer: 33 unit tests + 19 API e2e).

> The limitations listed at the bottom of ADR-0009 have since been closed — see
> **ADR-0010** and the revised "Known limitations" section below.

Run it yourself:

```bash
pnpm --filter @river/poker-engine test
pnpm --filter @river/api test           # unit incl. TableRunner
pnpm --filter @river/api test:e2e       # needs docker infra up
```

| 1   | **Server-authoritative game state**           | `reduce(state, action, rng)` is the only writer. Clients never compute cards, winners, or pots — `table-projection.spec.ts` proves the deck/other hole cards never reach a client; `action-validator.test.ts` + `reducer/invalid-actions.test.ts` prove every client action is re-validated server-side. `apps/api/.../poker-gateway.e2e-spec.ts` proves it over real sockets.                                                                                                                                                                                                                                                                                                                          |

| 5   | **Split-pot tests**                           | `pot-manager/split-pot-scenarios.test.ts`: heads-up board-plays even split, 3-way even split, **odd chip to the correct seat (first contesting seat left of the button)**, and a split of a _side_ pot while the short stack takes the main outright. `splitAmount` unit-tested for multi-chip remainders.                                                                                                                                                                                                                                                                                                                                                                                              |

## Known limitations & edge cases

**Deliberately out of scope (per the product brief)**

- No rake, no real money, no deposits/withdrawals.
- NLHE cash only — no PLO/Big O/Hi-Lo, no tournaments/SNGs, no straddles, bomb pots, run-it-twice, or time banks.

**Deliberate rule choices (not bugs)**

- **Odd chips** go to the first contesting seat left of the button (the standard online / TDA rule). Some card rooms award them by high card by suit instead; we don't.
- A player who joins between the button and the big blind is dealt in from the next small blind rather than being forced to post immediately. Combined with the forward-moving big blind (below), every seated player still posts the big blind exactly once per orbit.

**Closed since ADR-0009** (see ADR-0010)

- ~~Moving button.~~ The engine now uses the **forward-moving big blind** with dead-button and dead-small-blind support — `assignPositions` advances the BB one live seat per hand; the SB/button can be dead. `GameState.smallBlindSeat` is `number | null`. Tested for orbit fairness with players joining/leaving.
- ~~No auto-muck.~~ A beaten player who called a river bet now **mucks** (`HAND_MUCKED`, cards stay hidden) unless they can still win or chop a pot they're eligible for. All-in hands are always tabled.
- ~~No disconnect grace timer.~~ `TABLE_DISCONNECT_GRACE_MS` (default 10 s): a disconnected player's turn resolves on the short clock; a returning player gets the full clock back.
- ~~`PlayerStatus.Disconnected` unused in the engine.~~ Removed from the engine enum; wire status is the per-seat `connected` boolean. `@river/shared-types` keeps the wire value.
- ~~Snapshot recovery arms the timer eagerly.~~ Recovery now waits for the first reconnect before arming, so a fully-abandoned table burns no timers.
- ~~Stateless access tokens.~~ `SessionBlocklistService` denylists revoked `sid`s in Redis (TTL = access-token TTL); logout, refresh-reuse and password-reset all kill the access token immediately. A Redis outage fails open (short TTL is the backstop).
- ~~No malformed-payload fuzzing.~~ `reducer/fuzz.test.ts` fires ~20k hostile `EngineAction`s and asserts `reduce` never throws, never mutates its input, and conserves chips. (It found and we fixed a real chip leak — see ADR-0010.)
- ~~No dedicated heads-up "blinds exceed a short stack" test.~~ Added in `reducer/betting-scenarios.test.ts`.
